## 建议验收顺序

1. 打开本轮长缆报告，确认公司为长缆科技集团股份有限公司、期间为 2023 年，切换 Overview、盈利质量、现金流、资产负债、关键报表。
2. 点击营业收入、总负债、经营现金流的依据，核对 PDF 物理第 7、68、74 页。营业收入应为 `1,042,170,722.20 元`。
3. 追问“本期营业收入是多少？请提供它的原文依据。”，点击回答的引用；再问报告数据中没有的内容，检查缺少依据的提示。
4. 在“文件”中下载 JSON 和 HTML；离线打开 HTML，检查章节和来源摘录。离线文件不提供在线追问与原 PDF 下载。
5. 返回“分析另一份报告”，从历史重新打开并刷新；再上传自己的 PDF，检查等待状态、真实数据和失败提示。

遇到问题时记录：报告/文件名、操作、实际结果和期望结果。由用户确认数字、结论语义与交互是否符合预期后，再安排下一轮。

## 用户验收反馈：首页示例入口

用户随后在首页演示卡片复现 `/examples/use` 成功、`/chat/react-agent` 返回 `The file_path input is invalid.`。此前财报专用路由的联调没有覆盖这个入口。

根因是示例接口在 Windows 返回反斜杠绝对路径，而聊天的 legacy 输入协议明确拒绝反斜杠。现已将示例响应序列化为正斜杠路径，保持聊天侧原有校验。新增真实 HTTP 路由之间的回归：示例返回值不经前端转换直接提交聊天，覆盖 CSV、中文 PDF 文件名及跨 owner 拒绝；修复前复现 400，修复后 6 项示例测试通过。测试替换了模型流，仅验证入口协议与文件可读性，不代表首页完整模型分析或浏览器交互已验收。运行中的后端需重启加载修复，再从首页重新加载示例。
