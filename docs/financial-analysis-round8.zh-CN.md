## 运行与验收

在仓库根目录构建一次导出组件（本机本轮已生成）：

```powershell
New-Item -ItemType Directory -Force .work/financial-analysis | Out-Null
node standalone/financial-analysis/build.cjs .work/financial-analysis/export-runtime.html --export-runtime
```

默认路径相对 skills 所在仓库；其他部署位置可在 `.env` 中设置 `DBGPT_FINANCIAL_EXPORT_RUNTIME` 的绝对路径。修改报告组件后重新构建。已登记的同版本文件不会被新构建覆盖。未构建时只有 HTML 导出返回明确错误，JSON 可用。

使用原有 Qwen 启动方式；日常 3000/5670 若已有旧服务，先在原启动终端退出旧进程，再启动，避免重复占用。本轮没有操作这两个端口的进程。

验收入口：`http://127.0.0.1:3000/financial-analysis`。

1. 从历史打开报告，确认公司、期间及来源属于同一文件；刷新仍可打开。
2. 在“文件”中导出 JSON/HTML，再刷新检查文件仍在；离线打开 HTML，切换章节和查看摘录。
3. 新建任务后在原执行详情查看真实耗时；模型分析中不应显示整体完成，也不能提前导出。
4. 使用 `?demo=1` 比较原演示。实际浏览器视觉与点击验收尚未完成。

## 第三份样本：发现问题，未通过数据完整性验收

选用巨潮资讯公开的[长缆科技 2023 年年度报告](https://static.cninfo.com.cn/finalpage/2024-03-15/1219307390.PDF)，共 199 页。原文件与核对产物保存在被忽略的 `.work/financial-analysis/round8/`，没有加入 Git。

物理第 7 页同时列出调整前/调整后数据；原实现曾将 2022 年总资产取成调整前 2,219,758,361.24 元，而调整后为 2,219,763,827.15 元。已渲染原页核对，新增规则使包含调整前/后子表头的区块停止沿用年度列映射，并增加回归测试；当前不冒充已经支持重述对齐。

修复后重新运行，仅可靠提取两期经营现金流（2023：209,041,584.22 元；2022：37,165,660.15 元），其他未识别项保持缺失，相关计算不补值。Qwen 保留 1 条现金流结论，状态为 partial；询问未识别收入时返回 insufficient，不编造金额。新任务记录了读取 31 ms、提取 17,157 ms、计算 15 ms、保存 0 ms、模型分析 11,152 ms；这是一次本机运行结果。

已定位剩余问题：金额与表头落在不同的细分列、表格跨页列宽改变，以及资产负债表使用年初日期。目前不应把该样本称为第三份成功财报，也不能据三份下载成功宣布整体 v1 完成。`live/` 是修复前诊断记录，`live-final/` 为修复后结果；旧测试快照不重写，避免破坏版本与导出一致性。
